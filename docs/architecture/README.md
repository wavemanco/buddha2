# System architecture

Open [the interactive diagram](buddha2-architecture.html) in a browser. Select a block or connection for its explanation and pinned source references.

The diagram shows the actual Harness² engine, a general agent-runner role (currently OpenCode), separate authoring/selection and generation model roles, our coupled Python package and provider/accounting controls, strategy artifacts, native NoveltyBench assessment, and passive Inspect export/viewing. It also marks the score-blind boundary: benchmark judgments do not feed the adaptation loop.

This snapshot describes the accepted three-pair execution kit at [commit b5a56b6](https://github.com/wavemanco/buddha2/commit/b5a56b6802e9f49ca4c97aed6059a3617af868a1), before fresh key entry. It does not claim that the remaining pilot has completed. Current execution status lives in the [current specification](../research/CURRENT_SPEC.md), separately from this architecture snapshot. Replaceable roles are distinguished from a universal plugin runtime or MCP server, neither of which is implemented here.
