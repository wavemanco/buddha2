## Use the offline tool

The functions live in [adapter.py](../../../followups/phase3a_rank_contract_v1/adapter.py):

1. `prepare(parent_B, task, strategy, context)` returns a sealed mapping and the actual rank request without dispatching it. Context must explicitly identify a synthetic caller/slot.
2. `synthetic_result_binding(prepared, raw_reply)` binds a supplied fixture reply to that preparation. It cannot authenticate a provider result.
3. `derive(parent_B, task, strategy, context, prepared, raw_reply, result_binding)` returns a sealed accepted/rejected derivation and, only when accepted, its unchanged canonical answer records in the new order.

The [verification entry point](../../../followups/phase3a_rank_contract_v1/verify.py) runs H01, the frozen inventory, one saved-parent demonstration and exact replay in the existing SDK-free Inspect image; it does not run an Inspect evaluation or build a viewer. Its command is `python -B -m followups.phase3a_rank_contract_v1.verify` with `PYTHONPATH=/code:/code/src`, the six explicitly retained inputs mounted read-only at `/inputs`, source/seed mounted read-only and a **fresh** output mount at `/out`. Use the exact Docker command/mount record in the verification evidence, replacing only the output namespace for a new offline replay. Do not overwrite a prior run.

The frozen manifest, case results, demonstration, replay, static checks, actual container/cleanup records, before/after preservation and independent review are retained in the new `phase3a-rank-contract-v1` evidence namespace. Test-generated replies/permutations are never imported as model-backed primaries or assessments.
