## Cause and offline verification

The saved editor tool block has `{type,id,name,input,caller}`, with `caller: {"type":"direct"}` and a legitimate own-workspace `read`. The frozen validator accepts exactly `{type,id,name,input}` plus optional cache metadata in assistant tool history. Its strict key check therefore rejects the normal extra caller field when echoed by the client. Anthropic documents this field for traditional direct client tools in its [tool-calling documentation](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling#the-caller-field-in-responses).

The rejected live second request itself was not retained. To verify the causal round trip, the same pinned OpenCode CLI and concrete SDK mocks were run with direct-caller response metadata. The frozen validator reproduced the failure after one mocked HTTP response. A candidate four-line correction completed the actual three-turn CLI tool loop, kept caller metadata unchanged on the wire, accepted an absent caller for backwards compatibility and rejected four unsupported/null/server/extra-field caller variants. No real provider or credential was used. Other tool, path, schema, identity, cache and accounting checks remain intact.

The candidate is **not applied to production**. Its [patch](evidence/phase3a-v1/caller-regression-v1/candidate.patch), [proof](evidence/phase3a-v1/caller-regression-v1/proof.json), exact function, full fixture requests and [manifest](evidence/phase3a-v1/caller-regression-v1/manifest.json) are reviewable. The original mock fixtures had omitted this normal field; their passing tests did not cover this real response variant.

This is an implementation failure. It supplies no evidence for or against the benefit of recursive adaptation or the quality of either procedure.
