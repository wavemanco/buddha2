# I1 — passive Inspect visibility trial

Definition 1.0, 2026-10-31, America/Los_Angeles. Authorized by the user's “So let's do that?” referring to the proposed passive Inspect trial after H1. This is one bounded offline engineering slice, not a Phase3A repetition.

## Objective and usable output

Determine whether Inspect AI makes retained Harness² evidence easier to navigate without changing its meaning or entering the provider path. Deliver a minimal repeatable importer, two-case viewable Inspect log, field comparison, reproducibility checks and an adoption/removal recommendation. Actual Harness² remains the engine and native benchmark assessment remains separate.

## Scope and inputs

Use exactly two closed, synthetic H1 cases from `runs/phase3a-history-compat-h1/verification-v3`: the normal `fixed-changed` native fixture and the rejected `baseline-loss` fixture. Bind their exact public input files and hashes before import. These are software fixtures; neither supplies a live result, learned improvement or scientific score.

Use an isolated, version-pinned Inspect installation. Inspect's MIT license and dependency closure must be reviewed before use. Package/source registry traffic is permitted only for environment setup and advisory checks; evaluation/import/tests run in network-disabled containers, without credentials, with read-only explicit inputs and fresh output roots. Do not modify the existing H1 environment or install into the host/project environment.

Prefer Inspect's public saved-log interfaces. If direct log construction suffices, do not run an evaluation task merely to create records; no model is selected or constructed. Otherwise explicitly use `model=None`, never an omitted argument that could inherit a default. The originating model and settings are imported provenance, not Inspect-served models. Unsupported names or shapes must fail without inference.

## Deliverables

1. A small importer and runnable checks under `followups/inspect_visibility_i1`, with a pinned isolated environment and use instructions.
2. A new evidence/output namespace, `runs/inspect-visibility-i1`, holding explicit input hashes, software/image identity, two replays and fidelity results. No old artifact is overwritten.
3. A viewable Inspect log containing both cases, original identifiers/status/error, exact recorded messages/output and source references where supported. Fields with no exact native representation remain losslessly labelled imported metadata or source attachments, not invented native events.
4. A concise report and updated current-spec navigation explaining what Inspect helps with, what remains custom, added dependencies/adapter work and the next decision.

## Exclusions

No provider bridge/proxy, provider or token-count calls, keys, native reruns, new judge/scorer, scientific metrics, benchmark expansion, human/CrPO work, paid-launch kit, pilot repetition, durable recovery system or platform migration. No generic plugin framework or dashboards. Do not mark a missing assessment as zero or convert a recorded failure to a successful native run. Viewer/log import success is distinct from case success.

## Completion criteria

- I1-1: Both imported cases retain exact IDs, native success/failure, error and missingness; scores/results remain absent. Scripted fixture outputs are conspicuously labelled synthetic.
- I1-2: Role/model/configuration, recorded usage/cost and all omissions match canonical evidence. Distinguish absent, explicit null and zero. Opaque signed history is retained in original artifacts without fabricating a successful reconstructed transcript.
- I1-3: Original input bytes and frozen H1/R3 sources/evidence remain unchanged; no private filename or real-provider stream is read, including metadata, and the original folder remains outside all reads/writes/mounts.
- I1-4: Import/test execution uses actual Inspect APIs in a network-none, read-only container. Block network/provider construction in the importer too; demonstrate containment and zero attempted model/provider calls. A loopback-only viewer may be used solely to display saved logs, without external network access.
- I1-5: Two fresh imports round-trip through Inspect's saved-log reader and yield identical semantic payloads and exact source attachment bytes. Runtime timestamps/IDs may differ and must be explicitly excluded from semantic comparison. Reject unknown cases, malformed status/config, incompatible hashes and escaped/private/link paths before opening them.
- I1-6: View both cases in Inspect's actual viewer, or record an explicit viewer limitation. Independent review of mappings/checks passes. Provide a benefit/removal ledger and go/no-go decision; a negative fit finding can close the trial honestly.
