# Working on Buddha2

Read [the documentation index](docs/index.md), [current status](docs/research/CURRENT_SPEC.md), [research method](docs/RESEARCH_METHOD.md), [phase definitions](docs/research/PHASE_DEFINITIONS.md) and [implementation decisions](docs/phases/phase-0/DECISIONS.md) before changing the project. Historical engineering and phase decisions remain in [AGENTS history](docs/archive/AGENTS_HISTORY.md).

- Trace the real path before editing. Reuse existing helpers and make the smallest correct change. Validate files, model responses and network input at trust boundaries; fail explicitly rather than silently substituting models, prompts, results or settings.
- Tests and fixtures are hermetic and offline by default. Never load real API credentials or make provider calls during tests. Live work needs an explicitly authorized scope, a conservative spending ceiling and the applicable accepted, source-bound launcher and independent gates. A planning document or source publication supplies no launch authority.
- Keep work and runtime mounts within approved project paths. Reject traversal, symlinks and reparse escapes. Do not read, log, copy or publish secrets, credential bindings, writer locks or raw provider streams. Use fresh output directories; preserve prior runs, failures, reports and provenance.
- Keep model IDs, effective prompts, template versions, dependency pins and source/study identities explicit. Effective changes require a new compatible identity and output namespace. Never rewrite frozen manifests, alter shipped results or retag an old artifact to make replay pass.
- Keep external assessments and judge text unavailable to score-blind proposers/selectors/reflectors. Do not tune against held-out outcomes. Label human-written procedures as fixed baselines; only logged model-authored harness changes count as adaptation. Disclose ranking, repairs, retries, fallbacks and all costs; preserve failed and ambiguous outcomes.
- Use the pinned native engine and assessment interfaces. Offline tests establish engineering coverage, not provider behavior, scientific effectiveness, human preference or readiness for live use. Preserve explicit limitations and negative results.
- Deliver bounded, reviewable slices. Freeze scope, inputs, controls and acceptance criteria before observation; do not start another phase, collect human ratings, contact readers or spend money automatically. Stop at the applicable review/acceptance gate.
- Run checks relevant to the change without weakening invariants. Retain third-party licenses and notices. Current public documentation is arranged for readers; frozen experiment replay uses its versioned source/provenance packet, not a renamed current checkout. See [publication notes](docs/PUBLICATION.md).
