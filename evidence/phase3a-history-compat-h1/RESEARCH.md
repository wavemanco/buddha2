# H1 research: reliable execution around an agent harness

Research date: **2026-10-30**. Scope: primary documentation, public source, merged changes and issue records. This note supports the [H1 offline checkpoint](../../PHASE3A_HISTORY_COMPAT_H1_DEFINITION.md); it authorizes no installation, platform migration, provider call or new experiment. Recommendations below are engineering judgments, not compatibility results. Actual Harness² remains the experimental engine, NoveltyBench remains a separately executed native assessment, and our intent/result/unknown ledger remains the dispatch authority.

## Decision

Resolve the signed-thinking boundary first. OpenCode already has the exact published filter correction; H1 definition1.1 prospectively selects only its Anthropic hunk in an isolated derived runtime. Reuse Microsoft's offline SDK-stream regression pattern and DeepSeek Harness's distinction between durable records, projections and keyless loop replay. Consider Inspect AI later as the first evaluation-platform candidate, through a separately defined offline spike whose success means removing existing work while preserving effective requests. Do not introduce several overlapping orchestration layers.

The present reliability work is external experimental infrastructure: faithful provider state, explicit accounting, bounded execution and auditable outputs. It supports a valid adaptation experiment; its engineering improvements are not themselves a measured Harness² adaptation result. A platform could supply portions of that infrastructure, but cannot establish our scientific contrast or make an uncertain paid request safe to repeat.

## Exact failure family and a solved precedent

The stopped R3 attempt completed four real solver rollouts and three normal editor sessions, all KEEP_BASE. Its exact-history gate failed before readiness publication: thirteen provider-returned signed thinking blocks with empty visible text were absent from later requests. This is the local finding recorded by H1, not a claim made by an outside source. No signed content, signature values or reasoning text are reproduced here.

Anthropic explicitly documents that an empty thinking string with a populated signature is a complete block, not missing reasoning. The assistant turn should be returned unchanged during tool use. Changing the display setting would change the request configuration; inventing text or adding whitespace would change signed state. Those are not faithful fixes. The same troubleshooting page distinguishes a genuinely absent thinking block on an adaptive turn from an empty but complete one. [Anthropic thinking troubleshooting](https://platform.claude.com/docs/en/build-with-claude/thinking-troubleshooting).

Microsoft Agent Framework encountered the closely matching empty-string-versus-absence bug. Stream aggregation collapsed empty thinking text to null; serialization then treated the signed block as an orphan and omitted it. [Issue 8168](https://github.com/microsoft/agent-framework/issues/8168) was fixed by [merged PR 8171](https://github.com/microsoft/agent-framework/pull/8171), merged September 9, 2026, as commit `2cb63d370efa63ed8d65e56f9636d2aa6f178156`. The change preserves an empty string when either input actually contains one, while keeping two absent inputs absent. Its regression uses typed Anthropic SDK stream events, aggregates the result and serializes the next assistant message, checking that thinking precedes the tool call. There is also an absent-value control. This is stronger evidence than a helper-only test or an issue proposing a fix.

The H1 local diagnosis identifies the first loss in OpenCode's empty-part normalization, not that Microsoft aggregation function. The installed baseline reports Git HEAD `23fb5e0516c99ac04a1aa46c193efda2e1b9bb24`, but already has a three-line Opus4.8 branch and a lockfile change. It must be identified by actual file hashes, not described as a pristine upstream pin. Those existing differences remain preserved.

OpenCode's [PR26276](https://github.com/anomalyco/opencode/pull/26276) merged May 8, 2026, as `4e14f79511728d04329da664b747dd0b359cf931`. Its [Anthropic filter](https://github.com/anomalyco/opencode/blob/4e14f79511728d04329da664b747dd0b359cf931/packages/opencode/src/provider/transform.ts) retains reasoning with visible text **or** Anthropic signature metadata **or** Anthropic redacted-data metadata. Empty ordinary text remains separately filtered. This directly addresses our observed loss. The full PR changes three files, including Bedrock/media behavior and related session tests; selecting the Anthropic filter hunk is not adopting the entire commit.

The first fixed stable release is [v1.14.42, published May 9](https://github.com/anomalyco/opencode/releases/tag/v1.14.42). Its immutable source commit is [23c6b69abf35314781b9a55a6530527094075505](https://github.com/anomalyco/opencode/blob/23c6b69abf35314781b9a55a6530527094075505/packages/opencode/src/provider/transform.ts); [v1.14.41's source](https://github.com/anomalyco/opencode/blob/8ba2a9171597262df9d19516c82a5e14f18f5c63/packages/opencode/src/provider/transform.ts) still drops empty reasoning. These immutable sources avoid relying on a stale search result for a current development path that now returns404.

The H1 source-tree audit counts 2,068 changed blob paths between the older v1.14.18 baseline and v1.14.42, including prompts, lifecycle code and the Bun lockfile. A full upgrade therefore changes much more than this defect. [H1 definition1.1](../../PHASE3A_HISTORY_COMPAT_H1_DEFINITION.md) selects only the published Anthropic filter hunk as a scoped backport into a new isolated image, with no new dependencies, Harness² source changes or scientific intervention. There is no provider-history rehydration: preserve blocks during client conversion, then reject later loss before admission. Actual round-trip compatibility and negative checks remain required; published source alone is not acceptance.

## What their reliability designs teach us

Inspect's [checkpointing documentation](https://inspect.aisi.org.uk/checkpointing.html) is precise about its boundary: registered agent state, configured sandbox filesystem paths and sample event/store history are captured. Arbitrary process memory, running tools and external side effects are not. Custom agents must participate, and checkpoints occur at turn boundaries. Consequently, placing an opaque Harness² invocation inside an evaluation does not automatically make its internal editor session resumable.

Inspect's [cost limits](https://inspect.aisi.org.uk/setting-limits.html) use model prices and observed token usage, checked around generation. They are useful limits, but not documentation of our maximum-liability reservation policy. We would retain our ledger until a separately tested replacement satisfies pending intents, unknown charges, concurrency and historical holds. Its native evaluator facilities could still reduce task/scorer/logging work without owning paid admission.

Harbor's [separate verifier environment](https://docs.harborframework.com/tasks/separate-verifier) is a useful benchmark-adapter precedent. Agent outputs cross through explicit artifacts into a separate grading environment, and saved trials can be regraded. Artifact extraction removes unsafe filesystem features, while contents remain untrusted. Reuse the separation principle: a benchmark should consume frozen outputs through a declared assessment boundary, rather than expose grader state to the adaptive engine.

Durable execution is not exactly-once external billing. [Temporal's activity contract](https://docs.temporal.io/activity-definition#idempotency) explains that an external action can succeed before the worker records completion; recovery can execute it again. Idempotency must be enforced by the called service or application contract. [DBOS architecture](https://docs.dbos.dev/architecture) likewise requires deterministic workflows and idempotent steps, and re-executes an uncheckpointed step. For an ambiguous paid request, our valid recovery action can be to retain a reservation and stop, rather than retry.

Retry layers require an explicit combined policy. The [Pydantic AI Temporal integration](https://pydantic.dev/docs/ai/capabilities/durable_execution/temporal/) warns that Temporal's default maximum-attempt setting can allow unbounded model activity re-execution and that SDK, transport and activity retries can multiply. Its [DBOS integration](https://pydantic.dev/docs/ai/capabilities/durable_execution/dbos/) documents default-off model-step retries, recommends disabling provider-client retries and describes streaming/cancellation boundaries. These are useful operational designs; adopting them without our no-resend condition would weaken this experiment.

Mature evaluation infrastructure also encounters translation bugs. Inspect's [closed issue 3798](https://github.com/UKGovernmentBEIS/inspect_ai/issues/3798) records OpenRouter reasoning metadata corrupted by an unescaped text-tag round trip. The open [Bedrock signature-loss report 5300](https://github.com/UKGovernmentBEIS/inspect_ai/issues/5300) and [Sonnet 5.5 bridge report 5970](https://github.com/UKGovernmentBEIS/inspect_ai/issues/5970) are relevant warnings, not independently reproduced findings here or evidence of merged fixes. Another abstraction layer needs its own boundary tests.

## DeepSeek Harness: reuse its testing ideas

DeepSeek's [architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) separates durable session facts from live agent events and capability extension points. Model history is projected from the session log; complete assistant settlements and failed attempts have distinct roles. Requests are frozen before streaming, and persisted generations are preserved rather than overwritten during migration. These are helpful precedents for reconstructable effective requests and immutable experimental evidence, independently of its everything-is-a-plugin implementation.

Its [LLM replay package](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/test-support/llm-replay/README.md) boots the real agent keylessly with recorded model streams. Sidecar fixtures represent pre-chunk throws, cancellation and hangs that completed settlements cannot reconstruct. Teardown checks complete consumption, and extra sessions fail explicitly. However, scripts bind sessions by first-call order, assuming sequential delegation; this is not an arbitrary standalone provider mock or proven concurrent-session replay solution. Reuse the failure-fixture approach and ownership checks, not an untested package transplant.

That distinction matters for H1: a happy-path fixture that returns only text and tool calls cannot detect our signed-empty-block failure. The realistic fixture must traverse streaming, storage, normalization and next-request assembly, and adverse cases must stop before further admission.

## TraceTrial-Bench: useful taxonomy, deferred benchmark

[TraceTrial-Bench](https://github.com/TraceLite-AI/TraceTrial-Bench) separates agent task performance from harness reliability across 95 mechanism-oriented tasks and seven dimensions: context, execution, governance, lifecycle, observability, tools and verification. Its [preprint](https://arxiv.org/abs/2610.32285) was submitted **October 23, 2026**; the repository's October 27 badge refers to later Hugging Face recognition. As of this review it is very recent work, not a mature independently replicated standard.

Its separation fits our situation: a completed answer does not prove faithful conversation handling, and a harness failure does not establish low model quality. The useful immediate reuse is a failure-attribution checklist linking authoritative traces to the failed mechanism. Do not add its 95-task evaluation to H1, replace NoveltyBench, import its reported scores as our validation, or expand this compatibility checkpoint into a benchmark project.

## Licenses, maintenance and adoption limits

Official repository metadata checked on October 30 reports MIT for [Inspect AI](https://github.com/UKGovernmentBEIS/inspect_ai), [LangGraph](https://github.com/langchain-ai/langgraph), [Temporal's Python SDK](https://github.com/temporalio/sdk-python), [DBOS Python](https://github.com/dbos-inc/dbos-transact-py), [Pydantic AI](https://github.com/pydantic/pydantic-ai), [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) and TraceTrial-Bench, and Apache-2.0 for Harbor. All were unarchived with recent pushes. These are maintenance signals, not compatibility certification or complete third-party dependency audits.

[Langfuse's license](https://github.com/langfuse/langfuse/blob/main/LICENSE) applies MIT to its core with separately licensed enterprise directories. DBOS's optional hosted Conductor uses an enterprise package; its local library does not require that service. DeepSeek explicitly describes a rapidly changing developer preview. Pinning, dependency/license review and protocol compatibility remain necessary before adopting any component.

## Bounded recommendation after H1

Finish H1's actual-boundary reproduction, scoped upstream client backport, pre-admission invariant and independent offline acceptance. Keep the R3 failure, source, cost and output evidence immutable. Prove empty signed, visible signed, redacted and absent-thinking cases without synthesizing or rewriting provider state. This remains a zero-provider-cost engineering checkpoint and establishes no live or scientific result.

Then define, rather than automatically execute, a small Inspect AI assessment-layer spike. Require actual Harness² invocation and unchanged native NoveltyBench scoring, exact effective-request equivalence, explicit model/settings mapping, zero-call replay, a crash/ambiguous-result test and a concrete accounting of code removed versus added. Reject the candidate if it mainly adds translation or duplicate state. If durability later dominates, compare DBOS against the current outer controller; consider Harbor when environment/benchmark breadth justifies its task format, and Temporal when distributed operations justify its infrastructure.

The preferred outcome is less custom reliability machinery with the same demonstrable invariants. Until that comparison exists, retain the tested ledger and native engines. No platform reviewed here was installed or experimentally validated; research used public primary sources only, with no provider calls or credentials.
